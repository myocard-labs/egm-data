# ClassifierBank format

`ClassifierBank` is the unified in-memory and on-disk data structure that
every ML classification task in this stack consumes. Source-specific
banks (synthetic, IAFDB) are read into the Pydantic models generated by
`myocard-egm-contracts`, then converted into `ClassifierBank` via the
converters in `src/myocard_egm_data/banks/converters.py`. Downstream code
(training, eval, viewer, paper figures) only knows about
`ClassifierBank`.

## Why this lives in egm-data, not egm-contracts

`ClassifierBank`'s in-memory form needs to be numpy-friendly (signal as
a `[N, T]` float32 array). A JSON-Schema-codegen'd Pydantic model would
declare `signal` as `list[list[float]]`, which is unworkable for ML. So
`ClassifierBank` is a pure egm-data concept; we own the schema
ourselves via `CLASSIFIER_BANK_VERSION` and document the on-disk layout
here.

If a second consumer ever needs cross-language validation of the
on-disk format, we'll promote it to a contracts schema. For now it's
not needed.

## Schema versioning

`CLASSIFIER_BANK_VERSION = "0.2"` (see `banks/classifier_bank.py`). The
convention follows the contracts: plain X.Y string, X bumps at the
first release, Y bumps on every dev-time structural change. Consumers
MUST refuse unknown major versions.

`0.2` (from `0.1`) added cross-artifact linkage: the bank carries an
optional top-level stable `id`, and the per-source / per-trace `bank_id`
became the source bank's stable `ArtifactId` (it was an integer index
into the `banks` list). This is a clean break from `0.1` — the reader
does not load `0.1` files (integer `bank_id`); pre-1.0 banks are
regenerated rather than migrated. The stable ids are validated against
the egm-contracts `common.ArtifactId` pattern at construction.

## In-memory shape

```
ClassifierBank
├── schema_version: str          # CLASSIFIER_BANK_VERSION
├── id: str | None               # this bank's OWN stable ArtifactId
│                                 #   (e.g. a predictions bank "upred_..._<date>");
│                                 #   None for intermediate / untracked banks
├── created_utc: str             # ISO 8601 UTC
├── labels: dict[int, str]       # label int -> human-readable string
├── banks: list[ClassifierBankMetaData]   # one entry per source bank
│   └── ClassifierBankMetaData
│       ├── bank_id: str         # the SOURCE bank's stable ArtifactId
│       │                        #   (e.g. "tbank_synthetic_..._<date>")
│       ├── bank_type: str       # "synthetic" | "iafdb" | ...
│       ├── bank_path: str       # source file path (provenance)
│       └── bank_metadata: dict  # generic provenance dict
└── traces: list[ClassifierTrace]
    └── ClassifierTrace
        ├── bank_id: str                  # references its source bank by stable id
        ├── signal: np.ndarray            # [T] float32
        ├── freq_hz: float                # sampling rate
        ├── amp_type: str                 # "mv" | "z_score" | ...
        ├── split: str | None             # "train" | "val" | ...
        ├── label_truth: int | None       # ground-truth integer label
        ├── prediction: ClassifierPrediction | None
        │   ├── label_pred: int
        │   ├── label_prob: float
        │   └── pred_logits: dict[int, float]
        └── trace_metadata: dict          # per-trace provenance dict
```

### Conventions in `trace_metadata`

The dict is generic but consumers rely on a few well-known keys:

- `patient_id: str` — required for the patient-aware splitter. Every
  converter sets it (synthetic stringifies `simulation_id`; IAFDB
  passes through the IAFDB patient id).
- Other source-specific keys are passed through verbatim from the
  source bank (`fibrosis_density`, `peak_to_peak_mv`, etc.) so analysis
  code can pull them when it wants.

## On-disk layout (HDF5)

All traces in a single ClassifierBank share the signal length T (Phase
1 constraint). Per-trace metadata dicts are stored as JSON strings, one
row per trace. Nullable fields use a sentinel-mask convention (`uint8`
column) rather than NaN-encoding, so a `label_truth` of 0 stays
distinct from "missing".

```
/                                ← root
├── attrs:
│   ├── schema_version: "0.2"
│   ├── id: stable ArtifactId (optional; attr absent when None)
│   ├── created_utc: ISO timestamp
│   └── labels_json: '{"0": "healthy", "1": "fibrotic"}'
├── banks/                       ← group, one row per source bank
│   └── datasets:
│       ├── bank_id            vlen-utf8[B]  (stable ArtifactId)
│       ├── bank_type          vlen-utf8[B]
│       ├── bank_path          vlen-utf8[B]
│       └── bank_metadata_json vlen-utf8[B]
└── traces/                      ← group, one row per trace
    └── datasets:
        ├── bank_id              vlen-utf8[N]  (stable ArtifactId ref)
        ├── signal               float32[N, T]
        ├── freq_hz              float64[N]
        ├── amp_type             vlen-utf8[N]
        ├── split                vlen-utf8[N] ('' for None)
        ├── has_label_truth      uint8[N]
        ├── label_truth          int64[N]
        ├── has_prediction       uint8[N]
        ├── pred_label_pred      int64[N]
        ├── pred_label_prob      float64[N]
        ├── pred_logits_json     vlen-utf8[N]
        └── trace_metadata_json  vlen-utf8[N]
```

## Performance note

The current converters round-trip per-trace signal data through
Python lists (the Pydantic codegen declares per-trace columns as
`list[list[float]]`). For Phase-1 bank sizes (~2000 traces × 512
samples) this is fine; if banks scale up significantly we'll add a
faster path that reads HDF5 directly into numpy and skips the Pydantic
intermediate, without changing the public converter API.

## Why no JSON Schema?

JSON Schema codegen would force the on-disk format into a Pydantic
model with `signal: list[list[float]]`, which makes the in-memory shape
unworkable for ML. Promoting `ClassifierBank` to a contracts schema
would also require a parallel numpy-friendly in-memory dataclass and a
converter between the two — strictly more code for no win at Phase 1.
We can revisit if a second consumer needs to validate against the
on-disk format independently.
